# Omnis Desktop - v2.2.10 Release (Setup & Patch Info)

## Release Metadata
- **Version**: 2.2.10
- **Build Status**: Nexus / Stable Release
- **Target OS**: Windows (nsis)
- **Release Date**: 2026-04-30

## Critical Updates & Fixes

### 1. Salestrack: Stock Pipeline Synchronization
- **Fixed "Record null not found" error**: Resolved a bug where creating a *New* Stock Pipeline entry crashed the backend because the frontend passed an empty/null ID. The form now correctly passes an empty string, and the backend safely intercepts `"null"` to initiate a fresh insert via `frappe.new_doc()`.
- **Fixed Stock Sync Crash (Missing Items)**: Resolved a critical issue where the entire backend API (`get_stock_pipeline`) crashed during synchronization due to requesting non-existent legacy column names (`proposed_order` instead of `proposed_order_quantity` and `ted` instead of `eta_beira`). 
- **Fortified Query Logic**: The backend now fetches all fields (`*`) to eliminate strict column mapping failures.
- **Robust Potential Customers Mapping**: Wrapped the child table ("Potential Customers") fetch in a defensive try/except block. If the child table DocType name is structurally different on the live server, the API will gracefully skip it instead of crashing, ensuring that the primary pipeline data (such as Bobcat items) will ALWAYS sync to the app.

### 2. Dashboard UI/UX Refinement
- **Removed Predictive Analytics Container**: Cleaned up the main dashboard by removing the Predictive Performance and Recent Orders containers to create a cleaner, more focused UI.
- **Improved Typography & Visuals**: Changed the font stack to `Inter` and reduced font weights in the charts to make text ultra-crisp and modern. Bar charts were also converted to flat, solid fill colors.
- **Dynamic Field Aliasing**: Enhanced `index.html` template rendering to automatically support both legacy and current column names (`proposed_order` vs `proposed_order_quantity`, `ted` vs `eta_beira`) to bulletproof the app against future Frappe schema changes.

## Deployment Instructions

### A. Backend (Frappe Server)
> **IMPORTANT**: This patch requires a backend deployment. The desktop app cannot sync properly without the fortified `omnis_dashboard.py` file running on the live server.

1. Upload the updated `omnis_dashboard.py` from the local workspace to your Frappe server.
2. Place it in the appropriate backend directory (e.g., `~/frappe-bench/apps/powerstar_salestrack/powerstar_salestrack/` or similar depending on the app name).
3. Restart the bench to apply Python changes:
   ```bash
   bench restart
   # or
   sudo supervisorctl restart all
   ```

### B. Desktop Client (Build Installer)
1. Ensure all dependencies are installed:
   ```bash
   npm install
   ```
2. Build the new installer:
   ```bash
   npm run build
   ```
3. The new installer will be named `Omnis_Setup_2.2.10.exe` in the `dist/` folder.

### C. GitHub Release
1. Commit and push the latest code to the `master`/`main` branch.
2. Create a new release tagged `v2.2.10` on GitHub.
3. Upload `Omnis_Setup_2.2.10.exe` and `latest.yml` from the `dist/` folder to the release artifacts.
4. Existing users will receive the update automatically via the built-in auto-updater once they launch the application.
